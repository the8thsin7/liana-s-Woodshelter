# Session Master

## Objet
Ce dossier constitue le point de reprise opérationnel des échanges humain–IA. Il sert à transformer une demande en décision, action, trace et prochaine étape, avec un minimum de texte et une maximum de vérifiabilité.

## Règle d’usage
1. Distinguer explicitement : fait source, interprétation, hypothèse, décision, action.
2. Lier chaque fait important à sa source officielle, au document concerné ou à une référence vérifiable.
3. Poser toute date dans une chronologie : date du fait, date de réception, échéance, date d’action.
4. Comparer les micro-différences de texte lorsqu’elles modifient une obligation, un droit, une preuve, un délai ou un risque.
5. Ne jamais stocker ici mots de passe, secrets, RIB, pièces d’identité ou documents sensibles bruts. Conserver seulement les références, statuts, décisions et chemins vers le stockage sécurisé.
6. Toute action externe irréversible (envoi, dépôt, publication, création/modification) doit être montrée à l’utilisateur et confirmée avant exécution.

## Protocole de traitement
### 1. Cadrer
- Objet exact de la demande
- Dossier concerné
- Résultat attendu
- Niveau d’urgence
- Échéance connue ou inconnue

### 2. Établir les sources
- Source primaire : document, acte, courrier, contrat, décision, texte officiel
- Source secondaire : explication, guide, échange, note
- Statut : obtenu / à obtenir / à vérifier / contradictoire

### 3. Construire la chronologie
| Date | Événement ou acte | Source | Effet / délai | Statut |
|---|---|---|---|---|
| AAAA-MM-JJ |  |  |  |  |

### 4. Analyser
- Faits établis
- Zones d’incertitude
- Différences textuelles significatives
- Risques, conséquences et options

### 5. Décider avec la matrice
Appliquer `DECISION_MATRIX.md`. La matrice rend visibles les critères, les notes, les poids, l’incertitude et la prochaine action.

### 6. Agir et tracer
- Action réalisable maintenant
- Personne / organisme cible
- Preuve attendue
- Date de relance
- Inscription synthétique dans `SESSION_LOG.md`

## Format de réponse standard
1. Verdict direct en une ou deux phrases
2. Faits et sources
3. Chronologie / différence textuelle si utile
4. Matrice de décision si plusieurs options
5. Prochaine action concrète, responsable et date

## Niveaux de priorité
- P0 — Critique : délai légal ou financier imminent, sécurité, risque irréversible
- P1 — Important : valeur élevée, blocage réel, action à faire sous 7 jours
- P2 — À programmer : utile, sans dommage majeur immédiat
- P3 — Parking : idée, recherche ou amélioration sans action justifiée maintenant

## Règle de reprise
À la reprise d’une session :
1. Lire `DOSSIERS_INDEX.md` et les dernières entrées de `SESSION_LOG.md`.
2. Identifier le dossier P0/P1 le plus actionnable.
3. Vérifier les échéances et les éléments nouveaux.
4. Présenter une courte matrice seulement si une décision est nécessaire.
5. Finir avec une prochaine action datée.
